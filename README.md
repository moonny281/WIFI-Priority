# WiFi 优先级（WifiPriority）

Windows 小工具：按你排好的优先级自动切换 WiFi，**同一个 WiFi 有 5G / 2.4G 时优先 5G**，并且**事件驱动、毫秒级响应**。

- 周围出现**更高优先级**的 WiFi（信号够强）→ 自动切过去
- 当前 WiFi **信号消失/过弱/断线** → 立刻回落到次优先级（或同一网络的另一个频段）
- **5G 优先于 2.4G**（可改成 2.4G 优先，或不区分频段）
- 桌面**悬浮框**显示当前 WiFi 与频段（可拖动、吸附四角、调透明度/大小、锁定穿透、随时开关）；**显示层级可选**：悬浮在所有窗口之上（默认）或只显示在桌面；切换过程中会显示“正在切换到 …”
- 托盘常驻、开机自启（任务计划 + 最高权限，登录后无需再点 UAC）
- 界面：云母白（Windows 11 Mica）/ 墨夜（深色）/ 跟随系统

## v1.1.6 更新内容

**修复：把热点关掉后程序还一直尝试连接；新增“最低连接信号”**

- **根因**：Windows 读到的附近网络列表是缓存。热点关掉后，它的条目（连同当时很高的信号强度）会在缓存里留好一阵子，程序以为热点还在，于是不停地去连一个根本不存在的网络。v1.1.5 去掉失败冷却后，这个问题更明显。
- **识别“已经消失”的缓存条目**：每个接入点条目都带一个“最近收到它的帧”的时间戳。热点还在时，每次扫描完成它都会更新；关掉后就不再变化。最近两次扫描完成之后时间戳都没变化的条目，判为已消失，不再参与选择。
  - 启动时缓存里就有的条目，要等第一次扫描完成后确认在场才会用（启动后约几秒）。
  - 热点重新打开、或换了接入点地址（手机热点常见）时，新条目会立即被认出来。
  - 驱动不提供时间戳，或超过 15 秒收不到扫描完成通知时，自动放宽（按“在”处理），不会因此永远不切换。
  - 设置里可以关闭：「忽略已经消失的网络」。
- **新增设置「最低连接信号 (%)」**（默认 50，0 = 不限制）：目标网络的信号达不到它就不去连，适用于所有“连到新网络”的情况（升级、回落、断网后重连）。日志里会写明“信号 xx% 低于最低连接信号 yy%”。
  - 它和“切换到更高优先级所需的信号”同时生效，取更大的那个；当前已连着的网络不受它影响。
  - 注意：断网时如果所有候选网络的信号都低于它，程序就不会去连；想放宽把它调低或设为 0。
- **断网状态下连失败的网络，先让下一个候选试一次**（15 秒内），不再在断网时只盯着它死磕。连上任何网络后立即失效。
- 取消了 v1.1.2 加入的“定向扫描”：识别过期条目需要“每次扫描都是完整扫描”，两者互相冲突。

## v1.1.5 更新内容

**去掉失败冷却：只要检测到目标网络就连接，连不上网再回退**

- **根因**：旧版“联网检测”每 4 秒 ping 一次，连续 2 次（约 8 秒）失败就把当前网络标记为“5 分钟内不可用”并回退。手机热点刚连上时 DHCP / 路由还没就绪，或运营商拦 ICMP，都会被误判成“无法上网”——表现就是“连上热点、显示连接失败、自动回退，然后 5 分钟内不再连热点”。
- **不再有任何“整个网络”的失败冷却**：连接没成功、联网检测失败，都不会再拉黑网络；目标网络还在、还是最优，就会再次连接。
- **联网检测改得更稳**：刚连上的 12 秒内不检测；ping 和 TCP 443 同时探测两个公共地址，任何一个通就算能上网；连续 3 次（约 9 秒）都不通才回退。
- **回退只对“当前连着的这个网络”生效，离开它就立即清除，不留记忆**：回退到下一个网络后，热点仍是更高优先级，只受升级冷却（默认 8 秒，可在设置里调）约束，冷却一过就会再次连接。
- 仍保留的两个防空转的小限制（都不是网络冷却）：系统直接拒绝连接请求时至少隔 3 秒再试；同一个 WiFi 的“指定频段”连续失败时，2 分钟内不再指定该频段（不影响连接这个网络）。
- 注意：如果某个热点真的没有互联网，它会每隔 “升级冷却 + 约 25 秒” 被连一次又回退一次。不想这样可以关掉“联网检测”，或把升级冷却调长。

## v1.1.4 更新内容

**修复：软件运行时连不上手机热点（退出软件就能连），优先级最高的热点出现时不自动切换**

程序在三个地方会干扰连接，本版全部处理：
- **换到另一个 WiFi 时不再指定接入点（BSSID）**：BSS 列表是缓存，手机热点的接入点地址经常变化（随机 MAC、开关热点后换地址），指定缓存里的旧地址会连不上，4 秒后还会把热点拉黑 30 秒——表现就是“热点出现了却不切，手动连还回退到第二优先级”。现在只有同一个 WiFi 在 2.4G/5G 之间选频段时才指定接入点，失败时仍会先不指定重试一次。
- **正在连接时不扫描**（含用户在 Windows 里手动点的连接，和程序自己刚发出的连接请求）：有些网卡驱动在关联过程中被扫描打断会直接报“无法连接网络”，手机热点响应慢，更容易中招。
- **刚断开的 1.2 秒内不抢着连接**：你在 Windows 里手动换网时，系统会先断开再开始连接，中间有一瞬间是“未连接”，旧版会在这一瞬间发起自己的连接，把你的连接打断。注意：只影响“已完全断开”的情况，当前网络信号变差的回退不受影响。

如果热点出现后仍不切换，打开日志页，找 `优先网络 … 暂不切换：…`、`没有成功`、`检测到网络被手动切换到…` 这几类日志，把原文发出来就能定位。

## v1.1.3 更新内容

**修复：出现更高优先级的网络时不会自动切换（回退正常、升级不切换）**
- 原因：旧默认的频段策略「全局偏好频段优先」让当前连着的 5G 网络排到了列表里更靠前的 2.4G 网络之前，于是更高优先级的网络出现时，“最优”仍然是当前网络，永远不会触发升级；而回退不看排序，只在当前网络变差时才找次优，所以一直正常。
- 默认频段策略改为「仅同一网络内」：**列表顺序绝对优先**，同一个 WiFi 有多个频段时才偏好 5G。
- 旧配置自动迁移：原来是「全局偏好频段优先」的会改成「仅同一网络内」（启动时日志里会有一条说明），你自己调过的扫描 / 确认 / 冷却参数不受影响。想恢复旧行为，在 设置 → 频段偏好 里改回即可；之后不会再被改动。
- 仍选「全局偏好频段优先」的用户：当更靠前的网络因为这个策略被排在当前网络后面时，日志里会提示原因（5 分钟最多一条）。
- 频段策略的说明文字也同步更新，写明了“全局”策略下当前连着靠后的 5G 时，靠前的 2.4G 不会被切过去。

如果升级仍然不切换，打开日志页看有没有这几类提示：`优先网络 … 暂不切换：…`（信号低于升级阈值 / 没有已保存配置 / 刚才没连上或无法上网）、`检测到网络被手动切换到…`（自动切换被暂停）。把日志发出来就能定位。

## v1.1.2 更新内容

**修复：悬浮框只在桌面显示、盖不住其他窗口**
- 新增 **设置 → 桌面悬浮框 → 显示层级**：「悬浮在所有窗口之上」（默认）/「只显示在桌面」。
- 置顶模式下，显示后、设置变化后、前台窗口切换时都会重新置顶，另有每 2 秒一次的兜底，别的置顶窗口出现后悬浮框会自己回到最上面；重新置顶不会抢焦点。
- 局限：独占全屏的游戏 / 视频播放器会盖住任何普通窗口，程序无法改变。

**修复：出现更高优先级 WiFi 后切换慢、甚至不切换**
- **系统自行漫游不再被误判为“手动换网”**：换网之前原网络信号已低于回落阈值时，视为 Windows 自己在信号变差时漫游，不再触发“暂停自动切换”。（原网络信号突然消失、换网前信号仍然很高的情况，仍可能被当成手动换网——日志里搜“检测到网络被手动切换到”可以确认。）
- **防抖更抗抖动**：候选信号在升级阈值上下抖动、短暂（≤1.5 秒）掉出阈值时，不再把确认计时清零。
- **冷却只算真正的“换网”**：从未连接状态连上不再进入升级冷却；连接请求没被系统接受时也不占用冷却。
- **指定接入点（BSSID）失败先重试一次**：缓存里的接入点可能已经不在了，先改为只按配置文件重试，再决定是否拉黑，不再是“卡 4 秒然后整个网络 30 秒内不再尝试”。
- **看得见为什么没切**：排在当前网络前面的优先网络被挡住时，日志里会写原因（信号低于升级阈值 / 没有已保存配置 / 刚才没连上或无法上网），同一原因 30 秒最多一条。
- **看得见切换过程**：悬浮框在切换期间显示“正在切换到 XXX…”。
- **扫描请求被系统拒绝时不再空等 6 秒**。（原来的“定向扫描”在 v1.1.6 取消了。）

没有改动的取舍：升级阈值默认仍是 60%。高优先级网络信号低于它不会被切过去（现在日志会告诉你）；觉得偏严可以在设置里调低。

## 两个版本

| | WPF 版（`wpf/`） | Tauri v2 版（`tauri/`） |
|---|---|---|
| 技术 | C# / .NET 8，自包含单文件 exe | Rust + TypeScript，WebView2 界面 |
| 体积 | 约 60 MB（自带 .NET 运行时） | 约 10 MB，另有 NSIS 安装包 |
| 功能 | 完全一致 | 完全一致（含毫秒级切换、5G 优先、悬浮框、自启） |
| 配置 | `%AppData%\WifiPriority\settings.json` | 同一个文件，两个版本可以随时来回切换 |

> 两个版本**不要同时运行**（会同时去切换 WiFi）。开机自启各自用独立的任务名（`WifiPriority` / `WifiPriorityTauri`），只开其中一个即可。

## 为什么是毫秒级

旧版本每轮要启动 3 个 `netsh` 进程（几百毫秒）、再等 2.5 秒扫描、每 10 秒才轮询一次、还要连续确认 2 次。现在：

1. **原生 WLAN API**：直接调用 `wlanapi.dll`，读取当前连接 / 附近网络 / BSSID 只需进程内调用（通常不到 5 ms），不再启动任何子进程。
2. **事件驱动**：订阅 WLAN 通知（断线、连上、扫描完成），事件一来立刻评估；平时每 250 ms 用缓存数据评估一次。
3. **直接发连接请求**：`WlanConnect` 在进程内发出（可指定 BSSID 来选 5G/2.4G），不再 fork `netsh`。
4. **更短的防抖**：确认时间默认 400 ms（可设 0 = 立即），升级冷却 8 秒；**断线/未连接时不等确认，立刻连**；信号丢失的回落不受冷却限制。
5. **不阻塞**：联网检测放到后台线程；连接结果在后续评估里顺带检查，不再傻等。

日志页会记录每次切换从“读取状态”到“连接请求发出”的实际耗时。

**哪些仍然不是毫秒**（Windows / 硬件决定，程序无法加速）：

- 连接请求发出后，网卡与路由器的关联、认证握手通常需要几百毫秒到 1–2 秒。
- 发现一个**新出现**的更高优先级网络，取决于扫描完成的速度（一次完整扫描通常 1–3 秒）；程序默认每 3 秒请求一次扫描，可设为 0 = 连续扫描（最快，略费电）。Windows 可能对频繁扫描限流。
- 若原生接口不可用或校验失败，会自动回退到旧的 netsh 模式（较慢，日志会提示）。

## 5G 优先怎么工作

程序读取每个接入点（BSSID）的频段和信号，把“列表 × 频段”展开成候选项再排序。**频段策略**有三档：

| 策略 | 规则 |
|---|---|
| 全局偏好频段优先 | 只要有可用的 5G 网络，就优先于所有 2.4G 网络，其次才按列表顺序。适合 2.4G/5G 用**不同名字**的路由器（如 `Home` 和 `Home_5G`） |
| 仅同一网络内（默认，推荐） | 先按列表顺序；同一个 WiFi 同时有 2.4G 和 5G 时连 5G。你的列表顺序永远优先 |
| 不区分频段 | 只看列表顺序，同名双频由 Windows 自己选 |

> “全局”会让列表里靠后的 5G 网络排到靠前的 2.4G 网络前面，当前连着靠后的 5G 网络时，靠前的 2.4G 网络出现也不会切换过去。所以 v1.1.3 起默认改为“仅同一网络内”（列表顺序绝对优先）。

- 6G（Wi‑Fi 6E）排在 5G 之前；优先频段可改为“2.4G 优先”。
- 防抖：切到 5G 要求信号 ≥ 升级阈值（默认 60%）；5G 低于回落阈值（默认 40%）才退回 2.4G，中间 40–60% 不动。
- 同一个 WiFi 内换频段是“指定接入点（BSSID）重新连接”。如果路由器或网卡驱动不接受，程序会在日志里提示，并在 2 分钟内不再尝试指定该频段，不会反复断线重连。

## 切换策略（均可在设置里调整）

| 项 | 默认 | 说明 |
|---|---|---|
| 主动扫描间隔 | 3 秒 | 0 = 连续扫描；另外在断线、连上、系统唤醒、网络变化时会立即评估 |
| 升级阈值 | ≥ 60%（≈ −70 dBm） | 更优候选信号达到才会切过去 |
| 回落阈值 | < 40%（≈ −80 dBm） | 当前网络低于此值或消失，视为丢失；此时回落目标只要求 ≥ 此值 |
| 确认时间 | 400 毫秒 | 候选必须持续最优这么久才切换；0 = 立即 |
| 升级冷却 | 8 秒 | 两次“升级”切换的最短间隔，防止来回跳（回落不受限制） |
| 手动换网后暂停 | 10 分钟 | 你在 Windows 里手动换网时，不和你对着干（Windows 因原网络信号过弱而自行漫游不算） |

从 v1.1.0 升级时，旧的“10 秒 / 2 次 / 60 秒”默认值会自动迁移成上面的新默认值（其它设置保持不变）。

## 发布流程（全自动）

1. 改 `VERSION`（例如 `1.1.6` → `1.2.0`），提交并推送到 `main`。
2. 流水线自动：读版本号 → 构建 WPF 版和 Tauri 版 → 生成 `SHA256SUMS.txt` → 创建 GitHub Release `v1.2.0` 并上传所有产物，发布说明自动生成。
3. 不改版本号直接推送：只构建，不发布（产物在该次运行的 Artifacts 里下载）。`v1.2.0` 已经存在时同理。
4. 其它触发方式：推送 `v*` 标签（以标签版本号为准）；Actions 页手动运行（可选择是否发布）；Pull Request 只构建。
5. 版本号带 `-` 的（如 `1.2.0-beta.1`）会自动标记为预发布。

发布产物：

| 文件 | 说明 |
|---|---|
| `WifiPriority-wpf-v<版本>-win-x64.exe` | WPF 版，单文件、自包含，无需安装 .NET |
| `WifiPriority-tauri-v<版本>-x64-setup.exe` | Tauri 版安装包（NSIS，当前用户安装，无需管理员） |
| `WifiPriority-tauri-v<版本>-portable.exe` | Tauri 版免安装 exe（需要系统有 WebView2，Win10/11 默认自带） |

## 使用

1. 首次运行：到 **优先级** 页添加网络。已经在 Windows 里连过的网络直接填名称（或在 **附近网络** 页一键加入）；没连过的填名称 + 密码（仅支持 WPA2 个人版，WPA3/企业网络请先在 Windows 里手动连一次）。
2. 拖动条目（或点 ▲▼）排序，越靠上优先级越高。
3. **设置 → 频段偏好** 选择 5G/2.4G 的策略。
4. **设置 → 开机自启**：开启时会弹一次管理员授权（UAC），之后每次登录自动在后台运行。
5. 关闭主窗口只会最小化到托盘；托盘右键可暂停/恢复、显示/隐藏悬浮框、吸附位置、退出。

## 注意事项

- **位置服务**：新版 Windows 11 要求开启“设置 → 隐私和安全性 → 位置”，程序才能读取周围 WiFi。没开时概览页会提示并提供一键跳转按钮。
- 程序只能连接**已保存配置文件**的网络。原生模式下会自动使用 Windows 里该网络对应的配置文件名（不再要求与 WiFi 名称相同）。
- 权限：程序平时以普通权限运行；开机自启由任务计划以“最高权限”启动，因此不用每次 UAC。如果移动了 exe 位置，请在设置里关闭再重新开启开机自启。
- 配置保存在 `%AppData%\WifiPriority\settings.json`。

tauri/src-tauri/src/engine.rs  事件驱动引擎线程
tauri/src-tauri/src/parse.rs   netsh 解析（后备方案）
tauri/src-tauri/src/{tray,overlay,commands,ops,autostart,netsh,state,util,model}.rs，tests.rs 是决策器/解析器/配置迁移的单元测试
